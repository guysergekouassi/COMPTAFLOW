COMPTAFLOW — PAYLOAD REFERENTIEL
STATUT : CONTRAT APPLIQUÉ AUX ROUTES ET AU CONNECTEUR SELFLOW (19/11/2026).
Endpoint actuel : POST /api/external/referentiel/deverser
La route applique le middleware cle.entreprise. Le dossier est résolu depuis X-Company-Key ;
aucun secret global ni identifiant de société n'est requis dans le corps JSON.

PRINCIPE
Le dossier destinataire est résolu côté serveur à partir de la liaison authentifiée.
Le payload métier ne contient aucun comptaflow_company_id ni selflow_company_id
utilisé pour choisir le dossier.

CORPS JSON CIBLE
{
  "plan_comptable": [
    {"numero_de_compte": "601000", "intitule": "Achats"}
  ],
  "codes_journaux": [
    {"code_journal": "ACH", "intitule": "Journal des achats", "type": "Achats", "compte_numero": "401000"}
  ],
  "tiers": [
    {"numero_de_tiers": "FOU00001", "intitule": "FOURNISSEUR EXEMPLE", "compte_general": "401000", "type_de_tiers": "fournisseur"}
  ]
}

CHAMPS
- Plan comptable : numero_de_compte (numéro fourni par l'application source), intitule.
- Journaux : code_journal (code source), intitule, type, compte_numero.
- Tiers : numero_de_tiers (numéro source), intitule, compte_general, type_de_tiers.

NUMEROS ORIGINAUX ET UNIFORMISATION
L'application source ne transmet PAS numero_original.
Le numéro source transmis dans numero_de_compte, code_journal ou numero_de_tiers
est automatiquement conservé par COMPTAFLOW comme numéro original.
COMPTAFLOW génère ensuite son numéro interne selon la configuration du dossier.
Les écritures ultérieures utilisent le numéro source pour retrouver le référentiel.
Ne pas écraser un référentiel COMPTAFLOW existant sans règle explicite de mise à jour.

REGLES
1. Envoyer le référentiel avant les écritures.
2. Garder les numéros source stables et uniques par entreprise.
3. Ne jamais identifier un compte ou un tiers par son seul libellé.
4. Corriger toute réponse 422 et son tableau de refus avant de poursuivre.
5. Le rejeu doit rester idempotent.
6. Ne jamais accepter un identifiant de dossier libre dans le JSON pour router le dépôt.

AUTHENTIFICATION ACTUELLE
Le middleware cle.entreprise vérifie X-Company-Key, résout le dossier et bloque
les clés inconnues/révoquées ou les identifiants de routage contradictoires.
Le payload référentiel ne contient ni secret ni identifiant d'entreprise.
La gestion centralisée des applications client_id/client_secret et les jetons Bearer
reste à réaliser dans le chantier Liaison COMPTA-APK.
