LES 9 CHAMPS DU FICHIER TXT HISTORIQUE
1 Date de pièce
2 N° pièce
3 Code journal
4 Numéro facture
5 N° compte général
6 Libellé écriture
7 Montant débit
8 Montant crédit
9 N° compte tiers

Exemple TXT :
18/11/2026;OD-2026-00123;OD;OD-2026-00123;641000;Salaire novembre 2026;250000;0;
18/11/2026;OD-2026-00123;OD;OD-2026-00123;421000;Salaire novembre 2026;0;250000;

IMPORTANT : le TXT a neuf colonnes ; le JSON API n'est pas une ligne TXT. Le JSON porte compte_debit et compte_credit separement, plus les cles techniques.

CHAMPS JSON PAR LIGNE
date_ecriture, libelle, reference_document, code_journal, compte_debit, compte_credit, debit, credit, compte_tiers.
Cles techniques : cle_selflow/cle_source (unique par ligne) et operation_selflow/operation_source (commune a l'operation).

REGLES
- Envoyer une operation complete dans un lot atomique.
- Total debit = total credit.
- Journal connu ; aucun journal de substitution automatique.
- Compte et tiers resolus par leurs numeros/identifiants source.
- Cle de ligne stable pour eviter les doublons.
- Meme operation_selflow pour toutes les lignes de l'operation.
- Verifier la compatibilite des exercices.


EVOLUTION OBLIGATOIRE : le payload métier ne doit plus transporter selflow_company_id, comptaflow_company_id ni secret pour choisir/authentifier le dossier. L'identité applicative et la liaison déterminent le dossier côté serveur. Les numéros source des comptes, journaux et tiers sont envoyés une seule fois ; COMPTAFLOW les conserve comme numero_original et génère ses numéros internes. Cette évolution nécessite la migration des contrôleurs et des connecteurs : le contrôle du secret global historique est encore présent dans le code actuel.
